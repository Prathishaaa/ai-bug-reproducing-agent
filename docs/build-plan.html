AI Bug Reproducing Agent

You give it a bug from GitHub. It writes a test, runs it safely in Docker, and keeps trying until the test fails with the same error as the bug report.

How we work

  • I ask before I code. For each file, I explain in plain words what it will do. I write it only after you say OK.
  • One file, one job. Each file is about 40 lines or less, so you can explain every line.
  • One step at a time. A day is finished only when its "Done when" check passes.
  • Free tools only. Gemini free tier, Docker, pytest and Git.

2. Understand the bug
prompts.py + llm.pyDay 5

3. Pick the right files
pick_files.pyDay 5
Search the project's .py files for those keywords. Keep the top 3, so Gemini reads less and uses fewer free requests.
4. Guess the cause, write a test
prompts.py + llm.pyDay 8
Gemini reads the bug and the 3 files, gives one guess, and writes test_bug.py.
5. Run the test in Docker
docker_run.py + DockerfileDay 6
A sealed box: no internet, 512 MB memory, stops after 60 seconds. AI-written code never runs on your laptop directly.
6. Judge the result
check.pyDay 7
Python decides, not the AI. All 3 must be true: the test shows FAILED, the error matches the bug report, and the error comes from the project's own code.

ReproducedSave every attempt to results/L1.json (save.py, Day 10). Stop.
No

Build the parts

Each part works on its own before we join them.

Get the code and the bug report

download.py

  • Read bug L1's row from bugs.csv.
  • Clone the project into workspace/ and switch to the commit before the fix.
  • Fetch the issue from the GitHub API and save its title and text to a file.

Done when: one command gives you the code and a text file with the issue.

Understand the bug, pick the files

prompts.py, pick_files.py

  • Write the first prompt. Ask Gemini to answer only in JSON: error name, keywords, file names.
  • Search the .py files for those words and keep the top 3.

Done when: for L1 it prints OverflowError and the right file.

Build the sealed box

Dockerfile, docker_run.py

  • A 4-line Dockerfile: Python 3.12 with pytest.
  • Write the L1 test by hand first. No AI today.
  • Run it from Python with no internet and a 60-second limit. Mount only the cloned project.

Done when: your hand-written test fails in Docker with OverflowError, and an endless-loop test stops at 60 seconds.

Build the judge

check.py, test_check.py

  • The most important file. It checks the 3 rules from step 6 of the flow.
  • It catches a cheating test that simply runs raise OverflowError.

Done when: test_check.py passes on 4 saved outputs: a real match, a wrong error, a broken test and a cheating test.

Make it an agent

Join the parts and add the retry loop.

One full attempt

agent.py, prompts.py

  • Add the second prompt: give Gemini the bug and the 3 files, and get back a guess and test code.
  • agent.py calls each part in order: download, understand, pick, guess, run, judge.

Done when: python agent.py L1 runs the whole chain and prints match or no match.

Add the retry loop

agent.py, prompts.py

  • Try up to 4 times. Stop as soon as the judge says match.
  • Send each failed guess and its output back to Gemini.
  • If Gemini returns broken JSON, count it as a failed try. Do not crash.

Done when: you see the second guess change because of the first one's output.

Save results, clear error messages

save.py, agent.py

  • Save every guess, test and output to results/L1.json.
  • Show clear messages when Docker is off or the Gemini daily limit is reached.

Done when: L1 runs from one command and leaves a readable result file.

Prove it

Real bugs give you an honest number.

Try more real bugs

bugs.csv, Dockerfile

  • Check 5 to 10 more bugs from bugs.csv by hand: each must fail before its fix.
  • Install each project's packages while building the image, because tests run with no internet.

Done when: the agent has run on at least 5 real bugs, whatever the result.

Get your number

evaluate.py, results/summary.csv

  • Run every bug. Skip ones that already have a result, so a stopped run continues tomorrow.
  • Count bugs reproduced on try 1 and in any try. The gap shows what the loop adds.

Done when: you can say "X of Y real bugs" from your own results.
